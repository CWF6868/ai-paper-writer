发现（可直接写进简历/面试讲）：质检放行阈值 0.7 高于评审模型的实际打分中枢（0.44–0.64），导致每篇都必然触发一轮重写，重写机制退化成固定动作而非按需触发。修法：①把阈值下调到 0.6 左右或按分位数动态取值；②给评审 Prompt 增加分数锚点校准，拉开打分分布。

五、口径与可信度提示

  • 行覆盖率 98.99% 的范围是 backend/app/（1090 语句），不含 scripts/ 与 tests/。
  • 平均生成时长 119.0s 是端到端墙钟时长，不是单次 LLM 调用延迟，也不是并发吞吐。
  • 检索指标对外请报 Recall@1 = 85.2% / MRR = 0.926，不要单独报 Recall@5 = 100%：查询词取自文献原文（命中重合率 97.6%），语料仅 42 篇且主题差异极大（非命中重合率 14.0%），Recall@5 高属构造性结果，只证明链路通畅。
  • 检索评测集为自行标注的 23 条查询，存在「自己出题自己考」的局限；改进方向：加入同义改写查询与同主题 hard-negative 干扰文献。
  • 重写触发率 100% 是阈值标定的结果，不要写成「主动优化能力覆盖 100%」。
  • 本机无接口压测脚本与并发报告，不要出现 P95 延迟 / 并发 QPS 类数字。
  • 断点续跑只支持进程内（MemorySaver），不要写「支持 checkpoint 跨进程续跑」。
