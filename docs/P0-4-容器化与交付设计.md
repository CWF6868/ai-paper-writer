# P0-4 容器化与交付设计（第 2 步：镜像 + compose）

> 本文记录第 2 步的产物、验收证据与踩坑。第 1 步（演示模式）见提交 `573509f`。

## 一、目标

把「后端 + 前端」装进容器，一条命令拉起，数据卷持久化，PDF 中文不乱码，容器非 root，镜像体积受控。后续 CI（第 3 步）与公网部署（第 5 步）都复用这份镜像定义。

## 二、产物

| 文件 | 作用 |
|---|---|
| `backend/Dockerfile` | 多阶段：builder 出 wheel → slim runtime + 中文字体 + 非 root |
| `frontend/Dockerfile` | node 构建 dist → nginx 托管 + `/api` 反代 |
| `frontend/nginx.conf` | 静态资源 + SSE 不缓冲反代 |
| `docker-compose.yml` | backend + frontend + 命名卷 + healthcheck + depends_on |
| `backend/.dockerignore` / `frontend/.dockerignore` | 挡掉 `.env`、`data`、`node_modules`、`venv` |

## 三、验收证据（2026-11-03 实测）

| 项 | 要求 | 实测 |
|---|---|---|
| 首页 200 | 通过 nginx | `frontend=200` |
| 后端健康 | `/api/health` 200 | healthy（compose healthcheck 绿） |
| 全链路 | 登录→生成→SSE→导出 | `smoke_demo.py --base http://localhost:8080` 全绿 |
| PDF 中文 | 不乱码 | 字体解析到 `wqy-zenhei.ttc`，PDF 内嵌 CIDFontType2 + 真实中文字形 |
| 数据持久化 | down/up 不丢 | restart 后 papers 数不变（2 篇） |
| 非 root | uid != 0 | `uid=10001(appuser)` |
| 镜像体积 | ≤1.2GB | backend **1.01GB**，frontend 73.9MB |
| 冷启动 | 空卷首次部署可自举 | 空卷 `down -v` → `up`：**7s** 到 healthy，自动灌 42 篇语料 + 1 篇成稿；重启 6s |
| 回归 | 不破坏既有能力 | `358 passed`，覆盖率 93%（与改动前持平） |

## 四、踩到的坑（都修了）

1. **PDF 字体写死 Windows 路径**：`exporter.py` 里只有 `C:\Windows\Fonts\simhei.ttf`，容器里必然找不到 → PDF 导出报「未找到可用的中文字体」，但 docx 正常，极易被误判为"容器没问题"。修：候选列表扩展 Linux（wqy/noto/arphic）与 macOS（PingFang），并支持 `PDF_CJK_FONT` 环境变量显式指定；容器装 `fonts-wqy-zenhei/microhei`（约 20MB，比 noto-cjk 的 ~200MB 小一个数量级）。

2. **apt/pip 官方源慢到超时**：Debian 官方源 9.6MB 索引下了 45 秒没完，构建卡 30 分钟无输出。修：Dockerfile 加 `APT_MIRROR`/`PIP_INDEX_URL`/`NPM_REGISTRY` 三个 build-arg，默认官方（可复现），compose 透传。国内构建用阿里云镜像，全程 14 分钟（首次）→ 53 秒（缓存后）。

3. **SSE 被 nginx 缓冲**：默认 buffering 会让进度条卡到全写完才一次性刷出。修：`proxy_buffering off` + `X-Accel-Buffering no`，并放宽 `proxy_read_timeout` 到 300s（整篇生成是长请求）。

4. **探活打到前端静态页**：原冒烟脚本用 `GET /` 做健康检查，在 nginx 后面 `/` 是 index.html，后端挂了也 200。修：新增 `GET /api/health`（带 `demo_mode` 字段），冒烟脚本、Dockerfile HEALTHCHECK、compose healthcheck 全部改走它。

5. **镜像压线**：首版 1.21GB 超验收线。修：runtime 层清掉 pip/setuptools/标准库测试套件/编译缓存（约 50MB），落到 1.01GB。

## 五、已知边界（诚实说明）

- **单 worker**：SQLite + 本地 Chroma 都是进程内状态，多 worker 会各写各的（表现为"刚生成的论文刷新就没了"）。要横向扩容得先换 Postgres + 外部向量库，这是后续的演进项，不是本步范围。
- **SECRET_KEY 默认值**：compose 里演示环境共用 `dev-secret-change-me`，公网演示不承载真实用户，可接受；承载真实用户必须覆盖。
- **演示账号共享**：demo 账号所有访问者共用，公网部署时需定期重置数据或标注"公共沙箱"（第 5 步处理）。

## 六、本地验证命令

```bash
# 构建（国内建议加镜像）
APT_MIRROR=http://mirrors.aliyun.com PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple \
NPM_REGISTRY=https://registry.npmmirror.com docker compose build

docker compose up -d                 # 起服务
docker compose ps                    # 看状态（等 healthy）
# 全链路冒烟
cd backend && ./venv/Scripts/python.exe scripts/smoke_demo.py --base http://localhost:8080 --public
docker compose down                  # 停（数据留在卷里）
docker compose down -v               # 连数据一起删（演示环境重置）
```
