# 演示案例与截图指南

用于给本项目配一套「功能效果演示图」，贴进 README、评测报告或课程文档。

**核心思路：先造一个稳定存在的演示案例，再按分镜逐屏截取。**

不要「现场生成 + 现场截图」。因为一篇论文端到端生成约 **119 秒**（实测均值），现场截容易遇到三类翻车：列表是空的、进度条没截到、生成超时画面只剩「生成中…」。正确做法是**先真实生成一次，让成品永久留在库里**，之后每次演示直接打开就有内容；「生成中」的进度图另用一篇草稿专门跑一次来截。

---

## 一、演示环境准备（一次性，约 3 分钟）

1. 启动后端：双击 `start-backend.bat`，确认 <http://127.0.0.1:8000/docs> 能打开。
2. 启动前端：双击 `start-frontend.bat`，确认 <http://localhost:5173> 能打开。
3. 检查数据状态。当前库是干净的（`users` = 0、`papers` = 0），正好适合从零演示：

```bash
cd backend
venv/Scripts/python.exe -c "import sqlite3;c=sqlite3.connect('paper_writer.db');print('users',c.execute('select count(*) from users').fetchone()[0],'papers',c.execute('select count(*) from papers').fetchone()[0])"
```



> 如果上面不是 0，说明库里有旧数据，见文末「重置演示环境」。

## 二、构造演示案例（核心，只做一次）

### 2.1 演示账号

前端是 hash 路由，登录页地址是 \*\*<http://localhost:5173/#/login\*\*（直接访问> `/login` 会 404）。

点页面底部「没有账号？去注册」，填一套固定的演示凭据：

| 字段  | 值                  | 约束          |
| --- | ------------------ | ----------- |
| 用户名 | `demo`             | 至少 3 个字符    |
| 邮箱  | `demo@example.com` | 用假邮箱，别用真实地址 |
| 密码  | `demo123456`       | 至少 6 位      |

注册成功后会自动切回登录态，用 `demo / demo123456` 登录，进入「我的论文」。

### 2.2 主案例论文（用于成品展示）

登录后点「新建论文」，填写：

- **论文标题**：大语言模型在学术写作中的应用与挑战（必填，至少 5 字）
- **选题方向**：`自然语言处理`
- **关键词**：`大语言模型, 学术写作, 论文生成, 检索增强`
- **摘要**：可留空

点「创建」，回到列表后在卡片上点「查看 / 生成」，进入详情页，点 **「开始生成」**。

然后等 **100 ~ 140 秒**。期间右上角状态会依次经过：草稿 → 大纲 → 撰写中 → 审核中 → 已完成；进度区会依次点亮 7 个步骤：

```
选题分析 → 生成大纲 → 检索文献 → 撰写章节 → 整理文献 → 全文润色 → 质量检查
```

跑完后，这一篇就是你的**主案例**：带质量评审分数、论文大纲、完整正文、参考文献，并且三个导出按钮全部可用。它会一直留在库里，以后每次演示直接打开就有东西看。

> **当前状态**：库里已经有一篇跑完的《大语言模型在学术写作中的应用与挑战》——7624 字、6 个章节、5 篇参考文献、质量分 0.70，归属账号 `666`。登录后直接点「查看 / 生成」就能截图，无需重新生成。

### 2.3 进度演示论文（专用于截「生成中」）

再建一篇标题不同的草稿，例如：

- **论文标题**：`基于知识图谱的智能问答系统研究`
- **选题方向**：`知识图谱`

这篇**不要等它跑完**，只用来点「开始生成」后截「生成进度」那张图。截完可以删掉，也可以留着当第二篇案例。

> 为什么要两篇：主案例要保持「已完成」的干净状态，而进度条只在生成过程中存在，必须现场跑。两篇分开，互不污染。

## 四、怎么截才整齐

**统一窗口尺寸**（最容易忽略、但最影响观感）。10 张图尺寸不一致，插进文档会显得很乱。推荐固定成 **1440 × 900**，或 PPT 用 **1920 × 1080**。

最稳的做法是走 DevTools 的固定视口：

1. `F12` 打开开发者工具
2. `Ctrl + Shift + M` 切到设备模拟
3. 顶部「Responsive」下拉 → Edit… → 添加自定义尺寸 `1440 × 900`
4. 按 `Ctrl + 0` 把浏览器缩放恢复 100%
5. 用右上角 `⋮` 菜单里的 **Capture screenshot**（当前视口）或 **Capture full size screenshot**（整页长图）

**单张快截**：`Win + Shift + S` 框选，适合只截某个区块（如质量评审）。

**整页长图**：`F12` → `Ctrl + Shift + P` → 输入 `Capture full size screenshot` → 回车。适合「论文正文」这类需要连贯长图的位置。

**截前检查清单**：

- 只留一个标签页，关掉书签栏（`Ctrl + Shift + B`）
- 地址栏里的 id 无所谓，但别露出与演示无关的页面
- 成品页等状态变成「已完成」再截，否则右上角还是「审核中」
- 进度图必须在生成过程中截，跑完进度区就整个消失了

## 五、几个必然会踩的坑

| 现象                               | 原因                                            | 处理                                          |
| -------------------------------- | --------------------------------------------- | ------------------------------------------- |
| 列表页只有一句「还没有论文…」                  | 库里 0 条数据                                      | 先按第二节造出主案例                                  |
| 导出按钮是灰的点不动                       | 前端对 `paper.content` 判空，未生成时三个导出按钮都 `disabled` | 先生成成功                                       |
| 截不到进度条                           | 进度区仅在 `generating` 为真时渲染，全程约 2 分钟             | 点完立刻盯着，或先录屏再抽帧                              |
| 打开 `localhost:5173/papers` 报 404 | 路由用 `createWebHashHistory`                    | 必须用 `#/papers`                              |
| 生成报错「AI 服务余额不足」                  | DeepSeek / DashScope 额度或 Key 问题               | 检查 `backend/.env`                           |
| 改完 `.env` 仍提示「API Key 无效或缺失」      | `Settings` 只在进程启动时加载一次；`--reload` 只监听 `.py`，改 `.env` 不会热重载 | **必须手动重启后端**（关窗口重开 `start-backend.bat`）      |
| 参考文献为空 / 「检索文献」没有产出              | 向量库未灌入，或 Embedding 模型额度耗尽                  | `python seed_rag.py --check` 查数量；为空则跑 `python seed_rag.py` |
| 前端调不通接口                          | 后端没起，或后端换了端口                                  | 前端代理硬编码 `127.0.0.1:8000`，见 `vite.config.js` |

## 六、重置演示环境

想重新录一遍干净的演示：

1. 停掉后端（在窗口里 `Ctrl+C`）
2. 备份并删除数据库：`backend/paper_writer.db`
3. 重启后端，lifespan 会自动重建空表

```bash
cd backend
mv paper_writer.db paper_writer.db.bak   # 备份，别直接 rm
```

向量库 `backend/data/chroma` **不要删**，42 篇文献已在里面，删了要重跑 `python seed_rag.py` 花时间。

## 七、演示顺序建议

如果文档是按「功能」组织，配图顺序建议：

1. 认证（01、02）→ 说明数据按用户隔离
2. 论文管理（03、04）→ 说明 CRUD + 筛选搜索
3. AI 能力（05、06）→ 说明选题推荐与多 Agent 流式生成
4. 质量（07）→ 说明自动评审与重写机制
5. 产出（08、09、10、11）→ 说明大纲、正文、参考文献、多格式导出

这条线从「用户怎么进来」走到「拿到一篇能用的论文」，读者不需要额外解释就能看懂整条链路。
